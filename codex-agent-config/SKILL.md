# Codex 子代理配置

把用户需要的独立职责写成 Codex 支持的代理定义，交付文件、差异和验证结果。创建角色与启动角色是两个动作；仅要求配置时不要主动启动代理。

## 确定目标

先检查当前工具是否提供自定义代理能力，并用本机 `codex --version`（可用时）及 [官方格式说明](references/agent-format.md) 核对当前支持方式。不能因 TOML 可解析就宣称当前会话已加载。

- 已指定位置时沿用；否则默认项目 `.codex/agents/<name>.toml`。
- 只有用户要求跨项目使用时才选择 `$CODEX_HOME/agents/`；未设置 `CODEX_HOME` 时为 `~/.codex/agents/`。
- 从任务推断职责、输入、输出及禁止越界的动作。只问会改变角色行为、且环境和上下文无法回答的问题。
- 搜索现有代理的 `name`，包括项目和个人目录。遇到同名定义，展示冲突位置和最小差异；不能静默覆盖或无意遮蔽内置角色。

## 编写定义

每个文件提供非空的 `name`、`description`、`developer_instructions`。文件名与 `name` 保持一致便于查找。指令说明角色完成什么、需要哪些证据及输出给父代理的结果。

默认省略模型与推理配置，沿用父会话及已有默认值。仅在用户明确选择模型或推理强度后，按当前可用值添加对应字段；不借创建角色改变全局默认。

代理继承父会话的权限、提供商和 MCP。不要在角色中写入 `sandbox_mode`、`approval_policy`、`model_provider` 或 `mcp_servers` 来尝试覆盖父配置。行为指令中的“只读”不是独立只读沙箱。若任务需要更严的权限边界，说明应在父会话设置；不要自行改变它。

需要模板时读取 [K8s 审查角色](assets/k8s-reviewer.toml)，按真实任务修改；不要把模板的用途强加给其他角色。

## 最小更新与验证

1. 读取目标文件和相关现有配置；修改前说明影响目录，并保存原文件或可逆差异。已有明确授权不重复询问。
2. 只改请求涉及的角色与字段，保留注释、无关字段及其他角色。遇到当前版本不支持的字段先报告，不猜测兼容映射。
3. 对候选文件执行只读检查：

   ```text
   python -B <skill-dir>/scripts/check_agent.py <candidate.toml>
   ```

   工具要求 Python 3.11+，只检查 TOML、必填字段和明确无效的父会话覆盖字段，不验证全部产品版本或实际加载。
4. 查看最终 diff，核对默认未新增模型、权限或外部服务。用户要求实际使用时，另核对运行时提供的启动方式；不可用则报告配置已生成、加载尚未验证。
5. 交付路径、职责、检查结果及恢复原文件的方法；必要时说明需要新会话或重新加载，不宣称当前会话已改变。

用户需要创建可重复工作流程时，使用 `skill-creator`。父会话设置按当前 Codex 配置文档单独处理。
