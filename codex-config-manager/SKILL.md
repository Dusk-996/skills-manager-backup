# Codex 配置管理

把用户指定的设置变更落实到正确配置层，交付最小差异和验证证据。不要因为配置文件里有模型、权限或 MCP，就顺手修改这些内容。

## 先确认实际配置层

读取本机可用的 `codex --version`、当前调用参数和目标配置，核对当前官方 [配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)。只读取完成任务需要的键；不要输出认证材料、完整环境变量或其他无关私密配置。

| 请求范围 | 默认目标 |
|---|---|
| 当前项目的持久设置 | 项目 `.codex/config.toml`，须由当前环境信任后才会加载 |
| 跨项目个人默认 | `$CODEX_HOME/config.toml`；未设置时 `~/.codex/config.toml` |
| 仅本次调用 | 优先现有调用参数或会话设置，不擅自持久化 |
| 子代理职责与指令 | 使用 `codex-agent-config`，不要混入父配置 |

已有明确目标或范围时直接沿用；只有多个层级会产生不同结果且上下文无法确定时才询问。核对全局、项目及受管理要求的覆盖关系；文件保存成功不等于生效。

遇到字体、主题、自动保存等界面请求，先查当前应用确实支持的设置入口。没有对应 Codex TOML 字段时说明限制，不发明键或去改其他编辑器的 `settings.json`。

## 最小编辑

1. 根据请求列出要改的键、当前值、目标值、作用范围和生效条件。每个目标键都要有当前版本/官方资料支持；无法确认、已弃用或项目层不支持时停止这部分修改并说明原因。
2. 修改前说明影响范围，保存目标文件的原始副本与恢复位置；原文件不存在时记下这一点。已有授权不重复询问，不把安装本技能当作修改配置的授权。
3. 对目标文件做局部补丁，保留注释、格式、未知字段及无关值。不使用完整 TOML 反序列化再序列化覆盖。重复键、原文件无法解析或目标表含义不清时，先报告并限定修复范围。
4. 模型、审批、沙箱、信任、MCP 与外部连接仅在用户明确要求变更相应能力时修改。尤其不能为消除错误自动放宽权限或把不受信项目加入信任列表。
5. 新建文件只写请求所需的最小配置，不复制整份示例配置。项目不能覆盖的个人字段按 [层级和检查说明](references/config-checks.md) 处理，不默默写入另一个层级。

## 验证与交付

- 保存前后均验证 TOML 可解析，查看 diff 确认只改指定内容；检查值类型与支持范围。语法检查不代表字段被 Codex 接受。
- 若当前客户端提供安全的配置诊断或 schema 校验，使用与本机版本匹配的方法。没有对应入口时报告已完成静态验证、尚未证实运行态生效；不要猜测不存在的 CLI 子命令。
- 用户要求实际生效验证时，在符合当前权限且不会执行业务变更的环境中进行；需要重启或新会话时明确交接，不主动中断当前工作。
- 输出目标路径、变更键、差异摘要、已验证项、未验证项和回滚命令。回滚恢复原副本；原文件不存在时只撤销本次新建内容，避免删除后来新增的无关设置。

涉及 TOML 检查与隔离验证时读取 [配置检查说明](references/config-checks.md)。
