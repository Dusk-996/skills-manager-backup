# 按产品官网迭代个人技能

从技能实际指导用户执行的操作入手。例如一条 kubectl 命令、一个 API 字段、一项安装前提。先确定正文声明的适用版本、环境和用户有意保留的约定。多个产品分别核对，只把与这条用法有关的官方资料作为证据。

1. 定位官方版本化文档、迁移说明、CLI 帮助或发布说明中的具体段落，记下适用版本、链接和足以复核的事实。发布日期变了、官网改版或出现更高版本，本身都不需要改技能。仍受支持的旧环境保留原用法；必要时按版本补充分支。
2. 找出本地文件与官方事实的具体差异，例如现有示例使用了目标版本已经删除的参数。确认新用法仍满足原流程，不会顺便改掉国内镜像、集群命名、权限或用户的审批约定。对找不到证据的措辞偏好不发起改写。
3. 在临时区复制本地原技能为基线，再复制为候选，仅在候选中修订受影响的正文、脚本或引用。这里的基线是**本地修改前快照**。对可编辑的个人技能，用源码流程中的 `tree_sync.py` 预览当前安装、基线和候选，应用并保留独立备份；分发器所有的文件按其所有者流程处理。若本地在此期间发生冲突，保留用户改动。
4. 以读者会使用的入口验证，例如在所声明的 CLI 版本上检查 `--help`、使用配置语法检查或离线样例。无需访问生产集群或运行文档中的生产操作。报告修改的文件、旧用法、新用法、适用版本、官方证据和验证结果。依赖版本或来源无法确定时说清缺的证据。
