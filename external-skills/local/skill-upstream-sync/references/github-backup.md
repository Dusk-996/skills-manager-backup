# 发布到个人 GitHub 备份库

本技能为仓库所有者配置的备份目标是 [Dusk-996/skills-manager-backup](https://github.com/Dusk-996/skills-manager-backup)，Git URL 为 `https://github.com/Dusk-996/skills-manager-backup.git`。更新模式在本地验证通过后直接发布。此 URL 是备份的写入目的地；核对每个技能时仍应追溯其发布者。其他用户复用本技能时，使用其明确指定的目标。

## 收集本次应发布的文件

- 本地验证成功时，保存技能标识、仓库内路径、更新前后的文件清单与哈希、备份位置。将准备发布的准确内容保存在技能发现目录之外；如遇网络或鉴权失败，下次“更新”或“继续推送”可复用。待推送记录即使本地已是最新版也应处理。只检查、仅本地、无变更且无待传项目时均不提交。
- 使用备份仓库 `skill-catalog.json` 已登记的 `path`。首次归档按同类条目登记：独立个人技能放在 `external-skills/local/<名称>/`，已有中央管理技能沿用其登记目录。保留原许可证和归属说明；登记为 `inventory_only` 的项目按仓库约定仅维护元数据。
- 已登记的技能只移植本次验证通过的文件差异（含删除）；首次归档先核实构成该技能的文件。不要把整个个人目录、其他技能、凭据、私有运行配置、回滚快照、回执、数据库或缓存装入提交。若候选路径已有远端编辑，用更新前、本地验证结果、当前远端内容作三方比较。远端已有相同改动则记为同步，保留不相干改动，同文件冲突标明具体路径。

## 基于远端当前分支发布

1. 通过 `git ls-remote --symref URL HEAD` 确认远端默认分支及 SHA；用户指定分支时以该分支为准。用该 GitHub URL 建立独立干净的临时克隆，从远端当前 tip 开始。核对实际 push URL，只使用本机 Git 凭据管理器或已配置的认证。中央管理库有未提交或已暂存文件时仍可在隔离副本完成本次发布。
2. 将确认的变更移植到对应路径。新增技能时同步目录登记、统计和恢复说明；有场景图谱覆盖检查时加入最相关的现有场景。只更新内容的技能沿用现有登记。仓库有生成器时按需执行，例如 `python -B -X utf8 tools/build_index.py --check` 与 `python -B -X utf8 tools/build_atlas.py --check`。需要重新生成时用其 `--write` 再验证。
3. 以明确的文件路径运行 `git add -A -- <路径…>`，逐项复核 `git diff --cached --name-status` 和内容。仓库存在 `backup-manifest.json` 时，用本技能的 `scripts/backup_manifest.py --repo <隔离副本> --write` 对暂存的 Git 文件内容更新摘要，单独暂存清单并运行同一脚本的 `--check`。复查最终暂存路径和 `git diff --cached --check`。如果远端已包含全部结果，记录经核实的远端 SHA 即可。
4. 在隔离副本中以简短说明提交。明确指定唯一目标分支，例如默认分支为 `main` 时运行 `git push origin HEAD:refs/heads/main`。使用普通快进推送，不改写历史。推送后再次读取远端分支 SHA：与提交相同即完成；若远端已前进，抓取后以 `git merge-base --is-ancestor <本次提交> <远端提交>` 确认已包含。记录 `https://github.com/Dusk-996/skills-manager-backup/commit/<完整SHA>` 并清除对应待推送记录。
5. 网络返回不确定时先读远端确认是否已收到。非快进拒绝时，从最新 tip 重放本次改动并重算清单，复验后再推一次；遇到同文件冲突、认证失败或分支保护时保留本地成功结果、待推送补丁或隔离仓库的路径及提交 SHA，说明具体阻塞。若需撤回已发布的更新，从最新远端生成范围清楚的反向改动，重新验证并推送新提交。
