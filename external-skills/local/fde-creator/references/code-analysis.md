# 按章节追踪代码、字段与判断

在材料包含代码、SQL、配置、提示词或 Skill 时使用。目标是解释实现怎样承接本章知识，使学习者能理解结果、核查 AI 分析并判断交付条件，不把章节变成字段字典、文件摘要或缺陷审计。

## 先建立当前任务的关联链

根据任务书、README、版本说明及实际文件，识别当前入口、既有能力、客户待完成部分和证据角色。选择能解释本章核心知识的真实任务，先说业务目的、输入与预期输出，再沿入口、配置、模型或规则选择、工具计算、外部接口、结果与验证阅读。需要多条链时按知识关联组织，不按文件轮流概括。

跟踪实际导入、注册和分发关系：哪个入口调用什么、参数从哪里来、谁消费配置、相对路径基于哪里、结果由谁解释。从结果反向核查业务口径、源数据与期望依据；源码、测试、回放和运行记录不要互相替代。

## 选取真正影响结果的字段

优先解释影响业务结论、范围、权限、状态恢复或验收的字段，普通内部字段按需查阅。说明字段组合的业务含义，不要求枚举全部字段。解释时按需要覆盖：

| 维度 | 要回答的问题 |
| --- | --- |
| 业务含义 | 表示哪个对象、指标或状态；一行代表什么，粒度、单位、时间窗和去重规则是什么 |
| 来源与责任 | 来自客户、用户、配置、模型、程序计算还是外部响应；谁有权确认或改变 |
| 产生与使用 | 哪个文件或函数写入、转换和读取；经过哪些映射、关联或派生 |
| 校验与分支 | 类型、枚举、缺省、空值与零、跨字段约束、状态前提分别怎样检查；失败怎样处理 |
| 输出与证据 | 改变哪些计算、动作和呈现；可从哪个返回字段、日志、断言或样本核对 |

关键字段要与当前知识一起讲。例如筛选“会员所属门店”再汇总订单，与按“交易发生门店”统计含义不同，需核查实际关联键与查询，不能只根据 `store_id` 名称判断。

## 把条件与状态讲清楚

- **数据链**：核查源表或文件、关联键、派生逻辑、粒度、时间边界、单位、空值、去重与覆盖。最终 SQL 正确还需确认上游视图或派生表。存在记录不直接证明范围完整，缺覆盖不直接等于零或无人符合。
- **控制链**：找到参数被确认、校验和实际使用的分支。格式合法、业务范围合法、与用户意图一致分别验证；不能用其中一层检查概括其余层。
- **状态链**：区分 HTTP 状态、工具结果、Agent 整轮状态、持久化流程位置、动作账本和外部实际状态。解释谁在何种条件下推进、拒绝、修正或恢复，不把名称相同视为含义相同。
- **动作链**：核查身份来源、工具与动作许可、草案内容、确认绑定、执行与防重范围、超时后查询、并发及撤销条件。自然语言或工具内容不自动授予权限；流程保存点也不直接证明外部副作用只发生一次。仅解释已展示机制，不补想象中的保护。
- **模型与程序分工**：说明哪些是模型选择或生成，哪些是确定性计算、规则强制或人工确认；输出经过部分核查，不表示建议价值、所有用户条件或业务因果均已证明。

## 特别核对声明、实现与验证的距离

- 配置出现 `rules_file` 等键，先找到读取和消费逻辑；配置被读取，也不表示任意新规则都已可执行。需要确认计算、分支、输出和测试是否承接定义。
- `generated/` 等命名不证明来自当前输入；核查生成入口、依赖、版本与现有记录。README 启动命令也不证明启动成功。
- 测试代码说明设计了哪些检查，运行报告才支持特定版本下的执行情况。固定回复、Mock、参考 checkpoint 和教师结果不作为当前客户或当前模型的运行证据。
- 核对测试与 checker 的实际断言：schema、类型和必填检查不等于业务正确；文件存在、哈希匹配、状态声明、证据编号存在不等于内容真实充分。用独立期望核对结果，说明未覆盖项。
- 文档、源码、评估配置或契约不一致时，分别定位差异、适用版本与影响。正式任务要求不会因检查器漏检而减少，不以让测试通过为理由更改业务定义。
- 业务定义与实现冲突时保留双方依据，区分教学简化、阶段安排、客户差异、实现问题与待运行验证，不直接改代码。
- 配置只解释键名、用途与读取方式，不展示凭据。

## 用变化解释迁移与扩展

在影响理解的关键规则处，选取必要的条件变化，追踪它怎样影响字段、分支、结果、验证和承诺。例如阈值变更要核对实际传入与消费的值；目标或权限变化要核对原确认是否仍适用。基于已读规则作静态推导，标明辅助假设，不声称运行过，也不强制用户练习。

工程扩展从当前机制及限制引出：明确新增规模、并发、身份、数据或恢复要求，使学习者知道原实现在哪些前提下适用、需要增加什么原理与验证。不要把扩展简化为替换数据库、引入队列或学习框架的清单；具体技术选择须有场景依据。

## 面向代码较弱的学习者输出

先解释任务与数据如何流动，再说明关键规则落在哪些字段和代码位置，必要时展示少量原代码并解释语法在当前链中的作用。运维类比帮助衔接，不替代源码依据。

把发现转为 FDE 工作信息：该能力支持什么、受哪些数据和定义限制、需向谁核实、适配可能发生在哪里、用什么验证、目前可以承诺到哪里。代码语法理解、借助 AI 实现并验证、陌生环境迁移的要求分别说明。

阅读覆盖与学习要求也分开说明：本次追踪了哪些链路、仍缺哪些环节；学习者应能解释哪些结果、识别哪些推断越界、预测哪些变化、提出什么验证。静态阅读不声称已运行正确、已验收或生产就绪。
