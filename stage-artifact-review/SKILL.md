# 阶段产物复查

先找出要评价的阶段、路线及已约定范围、交付物版本、已确认的输入、证据位置和规则版本。一个文件可以贯穿多个步骤，按当前阶段实际出口评相关内容。以原文件、可打开的原型或实现和实际运行记录为准。同一份设计无需重抄。项目方提供三个通用维度、该阶段两个专属维度及预先声明的封顶条件。在 ops-vibe-coding 读取该项目修订中的 `references/stage-rubrics.md#sNN` 与共用计分方法。其他项目提供等效的已定版规则。找不到规则或版本有歧义，先报告所缺依据，暂缓评分。

1. 确认阶段是否到达。未到达写“未到达／不计分”。已到达并明确整份应交产物缺失时，列缺件，直接给 0/10、不合格。材料已交但无读取权限，写“待核验／不计分”，说明须开放的对象。部分缺件逐项评价，指出受影响的证据。按已约定的轻量或完整路线评分。
2. 逐项对照规则中的 0／1／2 分描述。写明产物位置、上游依据及其内容（路径加章节、样本 ID、决定人记录、测试用例或运行结果）。0 分说明缺失、错误或矛盾，1 分指出已有部分和可定位缺口，2 分给出支持证据。明确示例、假设与已验证事实。引用报告内自述时，核对它是否足以支持对应主张。
3. 把五项整数相加。逐条核对该阶段预先公布的关键条件。命中任一项，最终分取原始分与 7 的较小值；否则使用原始分。最终分至少 8 为合格。对每个扣分给一项可操作的修订建议和可观察的复验条件。
4. 单列阶段门禁和依据，沿用原门禁状态，包括受阻、待真人决定、失败或结束。失败用例如实上报可以得到满分，仍须交给相应责任人处置。评分本身不批准转换、风险接受或上线。
5. 只交付本次报告，不改受评内容、不触发下游或自动复评。人发起复评时引用上次报告、两版产物及证据。规则相同，逐条列出已关闭、仍存在和新发现的缺口，材料没变也可如实维持原结论。规则或实质评分范围改变，另列新基线，保留旧报告和差异说明。

## 报告格式

- 对象与版本、阶段和路线、上游范围及出口、规则路径与版本、首次评价或上次报告。
- 五行明细表，列为「维度｜得分｜判据和证据位置｜缺口、修改建议与复验条件」。
- 原始分、触发的封顶条件及依据、最终分、产物合格结论。对于缺件或不计分，说明原因；不补造逐项分。
- 阶段门禁、出处、责任角色和下一步；由人决定是否修订或复评。
- 复评附新旧版本和缺口对照；规则变化时报告新基线。
